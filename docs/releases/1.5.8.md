# OpenTailcat 1.5.8

Development preview, versionCode **47**, signed with the existing development key. The data plane remains a test-routing
preview and is not accepted for privacy-sensitive traffic.

## Changes

- Share a paired gateway's token as a QR code from the profile menu, without
  pasting it again. Each saved profile now has a QR action beside delete; the
  code contains that profile's stored token and should be shared only with
  someone trusted.
- Name the gateway in the QR dialog, so it is clear which profile is being
  shared.
- Keep the pairing dialog's "Show QR" available for a newly pasted token, as in
  1.5.7. The dialog still refuses to display an invalid token and still blocks
  screenshots.

## Verification

- Both GitHub and F-Droid debug unit tests and lint passed, including the QR
  encode/decode round-trip.
- QR scanning via an external app still requires an installed compatible
  scanner; OpenTailcat itself requests no camera permission.
- Production signing, upgrade lineage, physical leak capture, roaming, and IPv6
  WAN acceptance remain open. Reconnect attempts have no TUN between them;
  Android Always-on lockdown is required to block traffic during those gaps.
- Both ABI splits report versionCode 47 and the existing development certificate
  `dd767011a3d1223c6145cec024dccb02730e73607fc39544b2fac93adeafa8d6`.
