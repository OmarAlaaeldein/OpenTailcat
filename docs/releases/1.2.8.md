# OpenTailcat 1.2.8

Development build. Not a production privacy VPN. `ipv6` remains false.

Built with the `development` build type: release R8/resource optimization with
the existing development certificate and no debug UI tooling. `release` signing
remains separate; never debug-key-sign a release.

1.2.8 takes versionCode 21 to keep phone installs distinct from 1.2.7
(versionCode 20). It fixes the "connected, apps offline, then dies" class of
failure observed against a live user-controlled Tailcat gateway.

## What changed since 1.2.7

- Private-DNS trap closed: RFC1918, CGNAT (`100.64/10`), link-local, and IPv6
  ULA/site-local addresses are rejected as tunnel DNS in both Kotlin
  (`DnsValidator`) and native (`isSafeDNSAddr`) validation. The gateway refuses
  private destinations, so a LAN resolver previously blacked out all DNS while
  status showed CONNECTED. Saved profiles with LAN DNS fall back to `1.1.1.1`
  on load.
- Native pump panics contained: `recover()`-to-`markFailed` guards on TUN,
  gVisor, UDP, health, and flow goroutines turn a bad packet into FAILED plus
  clean teardown instead of aborting the app process.
- DiscoPing no longer kills a relayed tunnel: repeated disco misses downgrade
  transport and report additive `discoStale` (schema still v2) instead of
  pump-fatal teardown. Health heartbeat tracks pumps-alive per tick; Kotlin
  still requires `RUNNING` plus fresh `healthUnixSec` for CONNECTED.
- Dead `GATEWAY_RESOLVER` option removed; stored values migrate to
  `PROFILE_RESOLVER`. Telemetry card shows DNS query, policy-rejection, and
  RTT-stale (relay) state to separate DNS outages from transport outages.
- Version bump to 1.2.8 / versionCode 21. AAR rebuilt after the Go changes
  (Go 1.27.1 + NDK r29, 16 KB ELF alignment, verified Java signatures).
- Live evidence (host harness, compatible exit gateway): `prepare` handshake, gateway
  UDP DNS (TCP+UDP), and TLS egress to major hosts verified via
  `Client.DialUDP`/`Client.DialTCP` with `tcpOnly=false`. Full-device TUN
  connect on the emulator stays fail-closed (`LOCKDOWN_REQUIRED` on S+).
  `ipv6` stays false.
