# OpenTailcat 1.2.6

Development build. Not a production privacy VPN. `ipv6` remains false.

Built with the `development` build type: release R8/resource optimization with
the existing development certificate and no debug UI tooling. `release` signing
remains separate; never debug-key-sign a release.

1.2.6 renumbers the 1.2.5 release work: remote `main` already shipped a 1.2.5
(versionCode 18) protect-sweep APK, so this release takes versionCode 19 to
keep phone installs distinct. It includes the remote H2-residual
prepare-socket protect sweep and NetworkCallback threading fix.

## What changed since 1.2.5

- Dead-code sweep (behavior-neutral): removed the unexported `readPCAP()`
  wrapper in `core-engine/phase8_pcap.go`, two unused imports, and two stale
  comment numberings. No API, capability, or telemetry change.
- `VpnStartupInstrumentedTest` now accounts for Android S+: reading
  `Settings.Secure always_on_vpn_app` throws `SecurityException` for
  third-party apps, so the pre-prepare Settings fail-fast cannot fire there.
  On API 31+ the consented retry expects fail-closed handshake failure with
  service cleanup; pre-31 still expects `LOCKDOWN_REQUIRED`. Stop assertions
  poll briefly because service destruction is asynchronous.
- Version bump to 1.2.6 / versionCode 19. AAR rebuilt after the Go cleanup and race fix.
- Live evidence (emulator API 37 + host harness, nullexit gateway): native
  `prepare` handshake succeeds through the app path; IPv4 TCP/TLS egress,
  native UDP DNS, and DNS-over-TCP verified via `Client.DialTCP`/`DialUDP`;
  the post-warm framework lockdown check returns `LOCKDOWN_REQUIRED` without
  Always-on (fail-closed, no default routes). IPv6 dials but egress TLS fails,
  so `ipv6` stays false.
- Native race fix (pre-existing, found by `-race -count` stress while cutting
  this release): `closeSession` snapshots `sess.bridge`/`sess.client` under
  `globalCore.mu`. Previously the async `markFailed` close raced with
  `AttachTun` publishing/clearing the bridge on the H3 dead-reader path.
  Verified with `-race -count=20` on `TestAttachTunRejectsDeadReader` plus
  full-suite `-race` runs.
