# OpenTailcat 1.3.4

Adds working split-tunnel exclusions: apps checked in Settings > Apps now
bypass the VPN while the tunnel runs.

## Feature

Through 1.3.3 the Settings > Apps tab stored exclusions, but Connect was
refused whenever the list was non-empty and
`VpnService.Builder.addDisallowedApplication` was never called, so no app
could actually bypass the tunnel.

In 1.3.4:

* `TailcatVpnService.vpnBuilder` applies each stored exclusion with
  `Builder.addDisallowedApplication` on both the warm (host-only) and routed
  (`0.0.0.0/0` + `::/0`) interfaces. The list is snapshotted once per start
  and filtered by the new `SplitTunnelExclusions` helper, which skips blank
  entries and packages no longer installed so a stale entry cannot fail
  `establish`.
* The split-tunnel Connect refusal is removed from
  `TunnelController.validateStartRequest` and the service startup path;
  `LeakGuard` is deleted and `LOCKDOWN_REQUIRED_API` moved into
  `LockdownProbe`. Lockdown still never gates Connect (status only).
* OpenTailcat's own UID is never on the list; the Settings picker filters out
  the app package. Magicsock/DERP bypass still relies on
  `VpnService.protect` (`TransportSocketProtect`), not app-UID exclusion.

## Behavior notes

* Checked apps use the device network directly. The tunnel is not leak-free
  while any app is checked; the UI says so.
* With Always-on VPN + "Block connections without VPN" enabled, Android
  blocks checked apps from the network entirely (documented platform
  behavior for disallowed applications under lockdown).
