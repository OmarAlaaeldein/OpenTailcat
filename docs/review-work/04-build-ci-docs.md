### Area 1: scripts/phase8 (shellcheck 0.x: phase8 scripts clean at default severity; build-aar.sh 2x SC2155)

- **[M] [test-methodology] core-engine/cmd/phase8-analyze/main.go:66-94, core-engine/phase8_pcap.go:283-359 — Analyzer has no positive control, so an uplink capture that never saw the phone PASSes.**
  The uplink test is only "probe destination IPs absent" (dst-only, any decodable packet counts); there is no requirement that the device's own traffic (its IP, or flows to the gateway/DERP endpoint) appears, packet timestamps are discarded (`pcapPacket` keeps only payload) so the two captures are never checked for time overlap, and the gateway test counts *any* packet to a probe IP, including the gateway's own port-53 traffic to 1.1.1.1/8.8.8.8/9.9.9.9. The 2026-09-23 run log (handoff.md:689-701) shows it: `outer.pcap`, which the same section admits is not the phone's hop, printed "PASS uplink". This is distinct from reviewer 1's "uplink ignores port 53" item: here a wrong vantage point, an idle interface or a stale gateway pcap all pass.
  Fix: require `--device-ip` and `--tunnel-peer`; FAIL unless the uplink has >= N packets device→peer inside the gateway capture's time window; on the gateway side count only non-53 packets whose source is the tunnel-side address; add e2e fixtures "uplink without device traffic → FAIL" and "gateway-only DNS to probe → FAIL". Effort M.
- **[M] [test-methodology] handoff.md:637-641, scripts/phase8/run-host-gates.sh:59-63, scripts/phase8/generate-probes.sh:19-22 — The documented recipe captures the Mac's `en0` as the phone "uplink".**
  On an ordinary Wi-Fi/switched LAN a Mac's `en0` (not in monitor mode) does not see the phone's unicast frames unless the Mac *is* the phone's router (Internet Sharing → capture `bridge100`) or the capture is on the AP/mirror port. handoff.md:629-631 says this in prose, but every copy-paste command (handoff, run-host-gates.sh "physical dual capture", generate-probes.sh usage) uses `CAPTURE_IFACE=en0`. Together with the finding above, following the recipe literally yields a false PASS.
  Fix: document one supported topology (Mac Internet Sharing + `bridge100`, or AP port mirror, or rooted `wlan0`) in the commands themselves, and have the analyzer's positive control (above) catch the rest. Effort S.
- **[L] [test-methodology] scripts/phase8/generate-probes.sh:43-56 — EXTENDS: "Local apps see connected then closed for unreachable hosts".**
  The "N/ROUNDS connects" count and the "no successful connect" warning are meaningless while the VPN is up: gVisor completes the local handshake before the gateway dial (the baseline review confirmed `nc -z 203.0.113.1 80` exits 0), so every probe "connects" even with a dead gateway. Probes also cover only IPv4 TCP/443, while the Phase 8 pass bar and live matrix (handoff.md:606-624) include UDP/QUIC, DNS, IPv6. The `$ip`/`$PORT` values are interpolated unquoted into the remote shell string (operator-controlled, low risk).
  Fix: send a request and require a reply (`printf 'HEAD / HTTP/1.0\r\n\r\n' | nc -w 3 ... | grep -q '^HTTP/'`), add `nc -u` probes to a controlled echo host and IPv6 probe addresses, validate `PROBE_IPS` with a regex. Effort S.
- **[L] [portability] scripts/phase8/capture-uplink.sh:39-47, scripts/phase8/capture-gateway.sh:38-46 — tcpdump fallback depends on GNU `timeout`, which macOS does not ship.**
  `capture-uplink.sh` defaults to `en0` (a macOS name), yet with `CAPTURE_SECONDS` and no tshark it runs `exec timeout ...` → exit 127 on a stock Mac (verified: `which timeout gtimeout` finds nothing here). The fallback also never uses `sudo` (tcpdump needs root/BPF access) and silently ignores `CAPTURE_PACKETS` when `CAPTURE_SECONDS` is set (the two are mutually exclusive anyway). Both capture scripts are 95% identical.
  Fix: one `capture.sh` with a portable bound (`tcpdump -G "$S" -W 1`, or background + `sleep` + `kill`), shared by uplink and gateway. Effort S.
- **[L] [shell-safety] scripts/phase8/capture-mac-host.sh:9-14 — Ctrl-C leaves a root tcpdump running; interface hard-coded.**
  The capture is started as `sudo tcpdump ... &` with no `trap`. Bash starts background jobs of a non-interactive script with SIGINT ignored; verified here with a stand-in (`sleep 300 &` survives a process-group SIGINT that kills the script). With the real command, Ctrl-C during the window exits the script and the root-owned full-snaplen capture keeps growing until killed by hand (unverified: whether this sudo build re-enables SIGINT for its child). The `sleep` also starts before the sudo password is typed, so the window is shorter than `CAPTURE_SECONDS`; `en0` ignores `CAPTURE_IFACE`; there is no `-h`.
  Fix: `sudo -v` first, then `trap 'sudo kill "$PID" 2>/dev/null' EXIT INT TERM`; honour `CAPTURE_IFACE`; or drop this script in favour of the unified capture script. Effort S.
- **[L] [privacy] scripts/phase8/capture-uplink.sh:28,42, capture-gateway.sh:28,42, capture-mac-host.sh:6,10 — EXTENDS: "~270 MB of decrypted phone traffic sits inside the repo directory".**
  The scripts are what put it there: defaults are `captures/*.pcap` inside the repo (relative to CWD for two scripts, `$ROOT` for the third), full snaplen (`-s 0`), no BPF filter (the Mac one only excludes port 22, so every app on the Mac is recorded), and default umask; the existing `captures/gateway.pcap` / `outer.pcap` are `-rw-r--r--`. The analyzer only reads IP headers and ports.
  Fix: `umask 077`; default output under `~/.opentailcat-private/captures/`; `-s 128`; a host filter for the device and gateway IPs; `sudo tcpdump -Z "$USER"` so the file is not root-owned. Effort S.
- **[L] [maintainability] scripts/phase8/run-host-gates.sh:35-45, core-engine/build-aar.sh:92-105, .github/workflows/ci.yml:35-45 — The sourcehash pipeline is copy-pasted three times.**
  The three copies must stay byte-identical (they already differ in `shasum -a 256` vs `sha256sum`, and all three share the known missing `LC_ALL=C`). run-host-gates.sh also runs `go test -race ./...` and then re-runs the `TestProbeIPs` subset (redundant).
  Fix: one `scripts/sourcehash.sh` called by all three, with `LC_ALL=C` inside. Effort S.
- **[L] [test-coverage] scripts/phase8/write_fixture_pcaps.py:18-31, scripts/phase8/e2e-analyze.sh — Synthetic fixtures don't cover the paths the real run used.**
  Fixtures are 34-byte Ethernet frames (IPv4 header only, total-length 20, no L4 header, proto 17), so e2e never exercises the DNS-skip, IPv6, or `LINUX_SLL2` (`tcpdump -i any`) framing that the 2026-09-23 capture actually used (SLL2 is covered only by a Go unit test). No fixture checks "uplink with no device traffic" or "DNS to probe IP only".
  Fix: add `--linktype sll2|en10mb`, IPv6 and TCP/UDP-port options, plus the negative cases above. Effort S.
- **[L] [test-coverage] handoff.md:648-653, scripts/phase8/ — Two acceptance checks handoff assigns to Phase 8 have no tooling.**
  "Force each native pump to fail and confirm routes are removed or lockdown blocks traffic" has no script or hook (there is no debug trigger to kill a pump on a device). The split-tunnel "inverse" evidence ("excluded UID probes must appear on the uplink pcap and be absent from the gateway pcap") can't be evaluated because `phase8-analyze` only implements absent-on-uplink/present-on-gateway. Fix: add `--mode bypass` (inverse assertions) to the analyzer and a debug-build-only broadcast that kills a named pump. Effort S–M.

- **[M] [supply-chain/reproducibility] app/build.gradle.kts:112, .gitignore:33 — Published APKs contain files from an untracked local jar, so they can't be rebuilt from a clean checkout.**
  `implementation(fileTree("libs", include *.jar, *.aar))` also picks up the gitignored `app/libs/libtailcat-sources.jar` (gomobile's sources jar, present only on the dev machine). AGP packages its 15 `.java` files as Java resources. Verified in today's `assembleRelease` output and in the **published** `OpenTailcat-1.4.0-arm64-v8a.apk` (sha256 `445b8d55…`): `com/tailcat/vpn/engine/Engine.java`, `go/Seq.java`, …, 57 KB. A CI or clean-clone build lacks them, so the release bytes depend on unversioned local state. The content isn't secret (generated bindings), but this defeats any "rebuild and compare" check and shows releases are built from a dirty tree.
  Fix: `implementation(files("libs/libtailcat.aar"))` (explicit; fails loudly if missing), and have `build-aar.sh` write the sources jar outside `app/libs`. Effort S.
- **[L] [build/R8] core-engine/build-aar.sh:127 (`-javapkg=com.tailcat.vpn`), AAR `proguard.txt` — EXTENDS: "ProGuard over-broad keeps". The AAR's consumer rule keeps the entire app, so trimming `proguard-rules.pro` would change nothing.**
  gomobile writes a consumer rule for the Java package prefix: `-keep class com.tailcat.vpn.** { *; }` (verified in the AAR and merged at `configuration.txt:140`). Because the prefix is the app's own namespace, R8 keeps every app class and member unrenamed and unshrunk. In the release mapping, all real app classes (UI, `TokenParser`, updater, service, ~179 entries) map to themselves; only 53 R8-synthesised lambdas are renamed. `go.Seq`/`go.Universe` and `com.tailcat.vpn.engine.*` are correctly kept (JNI is fine). There is no security impact (obfuscation isn't a control), but dead code (e.g. the reflection layer) ships and baseline P2 #14 "trim ProGuard keeps" can't take effect.
  Fix: bind with a dedicated prefix (e.g. `-javapkg=com.tailcat.vpn.nativebind`, which changes the Kotlin/reflection class names once), or strip the AAR's `proguard.txt` and keep only `go.**` plus the engine package. Effort S–M.
- **[L] [build] app/build.gradle.kts:7,22-26,64-72 — ABI splits depend on which task names were typed.**

### Area 4: CI details
- **[M] [CI/supply-chain] .github/dependabot.yml:11-14, .github/workflows/ci.yml:33-51 — Dependabot's gomod updates can't pass CI and have already made a release ship a stale AAR; the submodule is never updated.**

- **[M] [release-engineering] (no release workflow), .github/workflows/ci.yml:53-66 — EXTENDS: "public v1.4.0 release is signed with the Android debug key". Releases are built and uploaded by hand from the dev laptop, with no provenance.**
