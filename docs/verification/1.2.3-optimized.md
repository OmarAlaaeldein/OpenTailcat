# OpenTailcat 1.2.3 APK size correction

Date: 2026-09-05. This records the packaging correction after the initial
`v1.2.3` development prerelease. It does not constitute VPN release acceptance.

## Cause

The initial 1.2.3 uploads used the unoptimized `debug` variant. The preceding
1.2.2 APKs were minified. ZIP-entry inspection found the following ARM64 sizes:

| Component | 1.2.2 | Initial 1.2.3 |
| --- | ---: | ---: |
| Complete APK | 20,755,931 bytes | 36,953,635 bytes |
| Compressed DEX entries | 1,132,258 bytes | 16,961,989 bytes |
| DEX file count | 1 | 16 |
| Native libraries | 19,457,488 bytes | 19,484,656 bytes |

The increase was predominantly unshrunk Java/Kotlin dependencies and debug
tooling. The native engine was not responsible for the doubling.

## Changes

- Added the `development` build type in `app/build.gradle.kts`. It inherits
  release R8 optimization and resource shrinking, uses the existing development
  certificate, and does not inherit debug-only Compose tooling dependencies.
  Production `release` signing remains separate.
- Kept versionName 1.2.3 and advanced versionCode from 15 to 16 so the optimized
  APK can update the initial download. Download filenames remain unchanged.
- Added optimized APK builds to CI and documented reproduction commands in
  README and handoff. Updated the 1.2.3 release notes to describe the replacement
  artifacts and their actual build type.
- No application behavior, Go source, upstream submodule, or AAR was changed
  by this packaging correction. No VPN capability was promoted.

## Instrumentation experiments and limitation

The existing instrumentation suite was temporarily pointed at `development`.
Building the minified test APK first failed on Error Prone's compile-time
annotation referring to `javax.lang.model.element.Modifier`. A test-only warning
rule allowed compilation. AndroidJUnitRunner then failed before any tests ran
because `androidx.tracing.Trace` was absent from its runtime class path.
Retaining that facade in the app moved the failure to another removed shared
dependency, `kotlin.LazyKt`.

These were test-runner startup failures; the optimized app launched and reached
its existing Connect refusal through normal UI use. The temporary build-type
selector and both experimental rule files were removed. The final development
APK uses the existing release R8 rules, without those test-support additions.
The instrumentation suite continues to target debug. A pass of the full existing
instrumentation suite against the optimized APK is **not claimed**. Direct UI,
upgrade, service-cleanup, and artifact checks provide the verification for this
packaging correction.

## Reproduction

```bash
./gradlew assembleDevelopment testDebugUnitTest lintDevelopment
```

APKs are under `app/build/outputs/apk/development/`. Publishing copies them into the
project root as `OpenTailcat-1.2.3-{arm64-v8a,x86_64}.apk` and regenerates
`OpenTailcat-1.2.3-SHA256SUMS.txt`.

## Validation record

- Optimized application builds passed. Temporary minified instrumentation APK
  builds passed, but the runner could not start the tests, as recorded above.
- 49 development-variant unit tests passed during the temporary instrumentation
  configuration. The final `testDebugUnitTest` run also passed all 49 tests with
  no failures, errors, or skips.
- Lint reported zero errors and 16 existing warnings.
- Signature verification matched the certificate on both 1.2.2 and the initial
  1.2.3; replacing an installed original 1.2.3 APK with the optimized APK via
  `adb install -r` succeeded without uninstalling.
- Package metadata reported versionName 1.2.3, versionCode 16, the intended
  single ABI, and no debuggable flag. APK 16 KB ZIP alignment passed.
- Native library contents compared byte-for-byte equal to the original 1.2.3
  APKs. The AAR SHA-256 remains
  `188ee38c4708a05a398aab8e05f278ed3903d692eee304028a1eff83ae2fa084`.
- Before the final test-runner rule, direct UI testing of the optimized app
  confirmed launch and Connect reached the existing lockdown refusal without
  closing the app. This is not evidence of a working tunnel.
- The emulator was restarted after the maintainer disabled the machine.
- Final direct UI checks passed for app launch, VPN consent cancellation,
  consented retry reaching the existing lockdown refusal, continued process
  survival, VPN service cleanup, saved-profile retention after force-stop and
  reopening, and absence of an automatic reconnect after that failed start.
  The crash buffer was checked as part of each stage.

The final candidate APKs are approximately 20.8 MB for ARM64 (43.8% smaller)
and 22.2 MB for x86-64 (42.2% smaller). Each has one DEX file. Exact downloadable
APK hashes are supplied in `OpenTailcat-1.2.3-SHA256SUMS.txt`. DEX/native
fingerprints from the tested candidates are retained for comparison with the
artifacts packaged after the source commit; code must remain identical.

The direct UI procedure is to launch the actual optimized APK with VPN consent
revoked, press Connect and cancel consent, retry Connect and accept consent,
verify the existing lockdown refusal, check that the app process survives and
the VPN service is removed, and force-stop/reopen the app to check profile
retention without an automatic reconnect. The emulator's existing saved test
profile is used; the lockdown refusal occurs before a native gateway handshake.

## Limits

Testing uses an API 37 ARM64 emulator with 16 KB pages. The x86-64 APK is built
and structurally verified; x86-64 runtime and physical phones are not exercised
in this packaging correction. Lockdown startup, transport protection, and the
other previously identified VPN issues remain unresolved. `ipv6` remains false.

The original `v1.2.3` source tag is preserved. The replacement packaging source
is recorded under `v1.2.3-optimized`; the existing development prerelease page
references that tag. Publication replaces only the two APK assets and their
checksum file, then compares GitHub's asset digests with the local checksums.
No production signing or release-readiness claim is
made.
