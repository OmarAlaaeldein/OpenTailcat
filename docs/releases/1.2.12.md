# OpenTailcat 1.2.12

Development build. Not a production privacy VPN. Do not claim leak-free.

## Highlights

- **IPv6 client path promoted** (`capabilities.ipv6=true`). Android already
  installs `fd7a:115c:a1e0::2/128` then `::/0` after pumps; the engine proxies
  IPv6 TCP/UDP when the gateway has IPv6 WAN.
- **Prepare-time IPv6 egress probe** (TLS to Cloudflare DNS IPv6 through
  `DialTCP`). Session/stats expose `ipv6Egress`. UI shows **IPv4 egress** when
  the probe fails.
- **Happy Eyeballs fix**: when `ipv6Egress=false`, public IPv6 flows are
  fail-closed immediately (TCP RST / UDP drop) instead of accepting a tunnel TCP
  that later blackholes on an IPv4-only WARP/gateway path. That stall was the
  likely cause of Google/Meta hanging while DuckDuckGo (IPv4-first) still worked.
- Android `satisfiesRouteRequirements` now requires `ipv6` by default (matches
  always-installed `::/0`).

## Live evidence (this release)

- Host harness + live token: `Prepare` OK; `tcpOnly=false`; `ipv6Egress=false`
  (gateway TLS to `[2606:4700:4700::1111]:443` reset — WARP/nullexit path is
  IPv4-only). IPv4 TLS to `1.1.1.1:443` through the same tunnel succeeds.
- Unit tests cover fail-closed public IPv6 without egress and full dial budget
  when egress is latched.

## Gateway dependency

True dual-stack Internet egress requires the exit-node / WARP path to forward
native IPv6. Until then OpenTailcat keeps `::/0` (no IPv6 bypass) and forces
apps onto tunneled IPv4. Do not treat `ipv6=true` as proof the live gateway has
IPv6 WAN — check `ipv6Egress` in telemetry.

## Not claimed

Phase 8 physical dual-capture / leak-free / production signing. Always-on
lockdown still required on Android 10+.
