# OpenTailcat 1.2.9

Development build. Not a production privacy VPN. `ipv6` remains false.

Built with the `development` build type: release R8/resource optimization with
the existing development certificate and no debug UI tooling. `release` signing
remains separate; never debug-key-sign a release.

1.2.9 takes versionCode 22 to keep phone installs distinct from 1.2.8
(versionCode 21). It keeps all 1.2.8 behavior and makes data-plane failures
diagnosable instead of reporting a bare "VPN data plane failed".

## What changed since 1.2.8

- Structured teardown reasons: `EngineHealth.teardownReason` distinguishes
  pump failure (with native detail), transport loss (RUNNING without a direct
  or DERP path), and stale health (with age and state). Teardown banners always
  name the cause, e.g. `VPN data plane failed: no fresh engine health for 42s
  (state RUNNING)`. `shouldTearDown`/`shouldConnect` semantics unchanged.
- Debug diagnostics flag: new opt-in `debugMode` preference (off by default,
  encrypted store) with a Settings → Connection → Diagnostics toggle. When on,
  failure banners append a raw telemetry snapshot (state, transport, tcpOnly,
  health age, RTT, DNS/TCP/UDP counters, drop counters, egress error), and
  telemetry-loss reports name the consecutive-failure count. Reporting only:
  the flag never gates routing or lockdown.
- Tests: new `EngineHealthTest` (5 vectors); `ProfileRepositoryTest` fake
  extended for the new preference.
- Version bump to 1.2.9 / versionCode 22. No native changes since the 1.2.8
  AAR; no AAR rebuild required.
