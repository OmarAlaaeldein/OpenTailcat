# OpenTailcat 1.7.0

## Changes

- **Share this phone.** The app can now be the exit gateway as well as the
  client. Tap the share icon on the home screen, pick a duration and who can
  connect, and the phone mints a one-session `tc…` code (QR and Copy). A guest
  pastes it into **Pair another gateway** and their TCP and UDP traffic leaves
  through this phone's own network. Every new device waits for your approval by
  default; **Anyone with the code** is an explicit mode that is always
  time-limited. A foreground notification shows the device count and data moved,
  and **Stop sharing** discards the session's keys, which revokes every code at
  once. Guests cannot reach the phone's own networks (loopback, private,
  carrier-internal, link-local, multicast are refused). Sharing and the VPN
  cannot run together; starting either while the other runs is refused.
- **Until I stop.** A share can run with no time limit instead of ending after
  at most 24 hours. It always requires approval, so a leaked code cannot give
  standing access, and it ends when you tap Stop sharing or Android closes the
  app (the keys die with the process).
- **Light text on buttons.** Filled buttons are white on a deeper teal instead
  of black on bright cyan, and chips, dialogs, menus and snackbars use the app's
  own dark surfaces instead of the stock purple and gray. Text contrast stays at
  WCAG AA, checked by a test.
- **DNS failover in the engine resolver.** It now starts from the Android DNS
  server that last answered and moves on after a timeout, instead of dialing
  only the first server. This fixes a failure to fetch the relay map on networks
  whose first DNS server never answers. It is partial: a flaky server can still
  cost one extra timeout.
- **Permissions.** Two are new and used only while sharing:
  `FOREGROUND_SERVICE_SPECIAL_USE` (the forwarding service) and `WAKE_LOCK`
  (held for the session, with a timeout). The privacy policy, which still
  described the old external QR scanner, is updated to match.

## Verification

Go: tests, race detector, vet, staticcheck and govulncheck. Android: 203 unit
tests per flavor, lint for both flavors, and the development APKs. On an API 35
arm64 emulator: sharing start, the foreground service, the notification, the
VPN interlock, and Stop (wake lock, service and notification released). By
hand: a physical phone connecting as a guest through an emulator host, over
mobile data, with approval and real browsing traffic (one capture showed about
170 open flows and 11 MB). Both APKs are signed with the pinned development key
and carry the configured updater repository.

Not done: battery and heat over long sessions (especially a share with no time
limit), a physical phone as the host, the instrumented and emulator suites, and
a run against a live gateway. The client tunnel changed only through the DNS
resolver fix, which has unit tests but was not re-checked against a live
gateway.
