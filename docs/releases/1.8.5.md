# OpenTailcat 1.8.5

The engine moves to Tailcat v0.8.0, an optional country filter is added, and the home screen keeps one layout when the gateway stops answering or the phone is narrow.

## Changes

- **Tailcat v0.8.0.** The pinned engine is the signed v0.8.0 tag. That pin fixes hangs when closing a client or server after many short connections, a UDP socket leak in region selection, crashes on null DERP map entries, and DNS on Android 9 and earlier. Hybrid (ML-KEM-768) tokens stay refused.
- **Country filter.** Settings can refuse tunneled connections to IP ranges allocated to selected countries. The list is a bundled snapshot of regional internet registry delegations and is best effort: CDN, anycast, and cloud ranges follow the registered country, not where a server runs. With any country selected, a failure to load that data refuses to connect.
- **Release notes in the app.** The notes for an available update can be read in full from Settings.
- **Home layout.** Share this phone is a labeled action under the connection card, and the connect ring uses the space above it. Status, path, address, and button labels stay on one line. A narrow phone or a large font no longer wraps a field or stretches a button. A gateway that stops answering turns the ring red and shows DEGRADED without moving the card or the share action.

## Verification

Host: 233 unit tests on each of the GitHub and F-Droid flavors, all passing. CI on the Tailcat v0.8.0 commit passed Go, the AAR rebuild, Android, translation, and emulator smoke. The live-gateway CI job does not run on pull requests.

On an API 35 emulator, at the normal width, with large text, and at about 360 dp: the connected home, settings fields and buttons, and the share screen, including the custom-relay fields. Pausing the live gateway showed DEGRADED with the ring red and the card unmoved; unpausing returned CONNECTED.

Development APKs for both ABIs, signed with the pinned development key, with the updater pointed at `OmarAlaaeldein/OpenTailcat`.

Not done this release: physical ARM64 dual-capture leak acceptance, a physical phone as the share host, and long-session battery and doze behavior. The client tunnel is still a development preview and not a hardened privacy VPN.
