# OpenTailcat 1.5.6

Development maintenance build, versionCode **45**. No data-plane behavior
change: `testRouting` remains true and artifacts remain development-signed.

## Changes

- Capability contract: `dataPlane` is derived from the individual flags by
  `routeReady()` instead of being set separately. `core-engine/testdata/capabilities.json`
  pins the payload, the Go suite fails when it drifts, and the Android suite
  reads the same file through a test source directory and requires it to satisfy
  the route requirements.
- Tests: Go covers each disabled capability and fixture drift; Android adds
  `testNativeCapabilityFixtureMatchesKotlinContract`.
- Docs: `AGENTS.md` condensed from phase prose to a working contract; README,
  SECURITY, privacy policy, and signing notes refreshed; stale Kotlin and
  Gradle versions corrected.
- Native: AAR rebuilt with Go 1.27.3 and NDK 29.0.14206865. No Java API change.

## Open items

Physical uplink and gateway capture, Wi-Fi/cellular handover acceptance, gateway
IPv6 WAN evidence, release-key backup, signing migration, and production release
checks remain open. Reconnect attempts have no TUN between them, so Android
Always-on lockdown is required to block traffic during those gaps.

## Build

```bash
env GOTOOLCHAIN=go1.27.3 core-engine/build-aar.sh
OPENTAILCAT_REPO_SLUG=<owner>/<repo> ./gradlew assembleGithubDevelopment
./gradlew assembleFdroidRelease -PnoAbiSplits
```

GitHub development APKs are split by ABI under
`app/build/outputs/apk/github/development/`; ship them under the
`OpenTailcat-<version>-<abi>.apk` names the in-app updater expects. F-Droid
release output is unsigned unless an explicit production signing configuration
is supplied.
