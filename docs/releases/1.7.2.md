# OpenTailcat 1.7.2

## Changes

- **Exit-node destination filtering covers the local-use NAT64 prefix.** A
  guest could previously hand the node an IPv6 address in the RFC 8215
  `64:ff9b:1::/48` prefix that the network translates to a private IPv4
  address, such as `192.168.1.1`. `exitnode/policy.go` now decodes every
  RFC 6052 prefix length and applies the IPv4 rules to the embedded address, so
  the local-use prefix is blocked exactly like the well-known `64:ff9b::/96`
  prefix. Carrier-specific NAT64 prefixes remain a known limitation because
  the node does not read the active network's prefix yet; this is recorded in
  `AGENTS.md`.
- **README and store listing present both roles.** The opening text and
  screenshots cover the client and Share this phone together.

## Verification

Go: tests, race detector, vet, staticcheck and govulncheck (no vulnerabilities).
The new policy tests cover the RFC 6052 `/32`, `/40`, `/48`, `/56`, `/64` and
`/96` layouts, including private, link-local and public addresses in the
local-use prefix.

Android: unit tests for both flavors, lint for both flavors, the F-Droid release
and GitHub bundle build checks, and the development APKs. Both APKs are signed
with the pinned development key and carry the configured updater repository.

Not done: a physical phone as the host, battery and heat over long sharing
sessions, a live-gateway run, and carrier-specific NAT64 prefixes.
