# OpenTailcat 1.3.5

Fixes the Settings > Apps split-tunnel picker to show every app installed on
the phone, and adds a search field.

## What was wrong

Through 1.3.4 the picker enumerated apps with `LauncherApps.getActivityList`,
which only returns apps that have a **launcher icon**. Background and headless
apps — the ones most useful to exclude — never appeared in the list.

## Changes

* The picker now enumerates every package installed for the user with
  `PackageManager.getInstalledApplications`, filtering blank labels and
  OpenTailcat's own package, sorted by app name.
* New search field filters the list by app name or package name.
* Added the `QUERY_ALL_PACKAGES` manifest permission (normal level, auto
  granted; full package enumeration for a per-app VPN is a permitted use).
  Lint advisory suppressed with `tools:ignore` on that declaration.

## No other behavior changes

* Exclusions still apply at the next tunnel start via
  `Builder.addDisallowedApplication` on both the warm and routed interfaces
  (1.3.4 behavior).
* Checked apps still bypass the VPN by design; the tunnel is not leak-free
  while any app is checked. UI copy is unchanged.
* No native changes: AAR unchanged
  (`aa0fa1bdda9ae102d3ef7a7153c2d1ceca3f5165c8c707e8b490d97997a75999`).

## Verification

* `testDebugUnitTest` and `lintDebug` pass (zero errors).
* `assembleDevelopment` and `bundleDevelopment` succeed.
* Merged manifest contains `QUERY_ALL_PACKAGES`; dex contains
  `getInstalledApplications` and the search UI.
* Physical-device verification of the full package list and packet-capture
  split-tunnel acceptance remain Phase 8 work — see `handoff.md`.
