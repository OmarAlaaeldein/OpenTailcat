# OpenTailcat 1.7.1

## Changes

- **Sharing survives a stop/start race.** The exit-node service now carries a
  session generation and ends with `stopSelf(lastStartId)`, so a Start that
  Android queued around a Stop is delivered instead of dropped, and an older
  session can no longer remove the notification, wake lock, or service of the
  session that replaced it. The wake lock's timeout is replaced when a new
  share supersedes a stopping one.
- **Sharing stays responsive while it starts.** Starting a node can take up to
  30 seconds while the relay map is fetched. Device approvals and live stats no
  longer wait behind that work, and Stop cancels an in-flight start instead of
  blocking behind it. Start and stop requests are ordered, so a stop cancels
  only earlier starts and cannot close a newer session.
- **Bounded admission and peer state.** Open admission remembers at most 256
  idle device keys, and peer display records are capped at 512. Approved devices
  and active flows are never evicted; a forgotten open-admission device is
  admitted again on its next attempt.
- **Oversized UDP datagrams are dropped, not truncated.** A datagram larger than
  the tunnel payload limit is counted and dropped in either direction instead
  of forwarding a corrupted prefix.
- **Dependency refresh.** `golang.org/x/net`, `golang.org/x/crypto` and the
  matching `x/` modules were updated to their current releases, clearing three
  module advisories that current code paths did not reach.
- **Documentation.** The README now presents both roles up front and displays
  screenshots in standard Markdown tables. The stale exit-node plan and UI
  research note were removed, with the remaining limitations and open items
  consolidated into `AGENTS.md` and `SECURITY.md`.

## Verification

Go: tests, race detector, vet, staticcheck and govulncheck (no vulnerabilities).
Android: unit tests for both flavors, lint for both flavors, the F-Droid release
and GitHub bundle build checks, and the development APKs. Both APKs are signed
with the pinned development key and carry the configured updater repository.

Not done: a physical phone as the host, battery and heat over long sharing
sessions, and a run against a live gateway.
