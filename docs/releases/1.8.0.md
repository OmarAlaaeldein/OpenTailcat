# OpenTailcat 1.8.0

A hardening release. It fixes the findings of a security, concurrency, and UI
audit of the Go engine, the exit node, the Android services, storage, the
updater, and the Compose UI. There are no new features and no changes to the
token or capability formats.

## Fixed

### Data plane and DNS

- **IPv4-mapped IPv6 addresses bypassed the DNS safety checks.** They are now
  normalized before the DNS policy and `isSafeDNSAddr` judge them.
- **Reserved DNS resolver addresses were accepted.** CGNAT, NAT64, and other
  special-purpose ranges are now refused.
- **Abandoned async `DialTCP` connections were never closed**, and
  `netstackProxy.Close()` could hang on shutdown. Connections are closed and
  shutdown is bounded.
- **UDP flows that expired or were evicted could be reported twice**, skewing
  the unanswered-flow count that drives the TCP-only relatch. They are now
  reported once, and `relatchUDP` is waited for on close.
- **DNS-over-TCP sessions raced on read deadlines**, and framing and byte
  accounting had gaps. Deadlines are set under the session lock.
- **Truncated or fragmented IPv6 packets near the MTU could panic** the packet
  path. They are now dropped safely, with no bogus Packet Too Big.
- **The in-tunnel speed test had wrong timing and did not cancel cleanly.**
- **`UpdateNetworkState` kept IPv6 zone suffixes** from `LinkProperties`. They
  are stripped.
- **Fetched or cached DERP maps were not vetted.** Every decoded map now goes
  through `DERPMapFilter`, which strips unsafe STUN test IPs and drops the map
  on error.

### Tokens and relay settings

- **Go and Kotlin disagreed on some token edge cases.** Nested CBOR key length
  is capped, embedded DERP nodes with unsafe values are rejected, and the
  differential corpus was regenerated so both parsers agree.
- **Custom relay input was not fully validated.** An unsafe relay host or
  trailing JSON after the config is now rejected by the bridge.

### Exit node ("Share this phone")

- **A revoked guest could get back in** after enough other guests were denied,
  because the denial list was bounded and forgot old entries. Revocations are
  now permanent and never evicted, and a host refusal applies in open mode too.
- **An open-admitted guest forgotten by admission stayed connected** as a live
  WireGuard peer. Evicted peers are now disconnected.
- **Guests could reach the host's own network.** Destination filtering now also
  blocks the phone's own addresses and on-link LAN prefixes, ::/96
  IPv4-compatible addresses, SIIT, Teredo, 6to4, local-use NAT64
  (`64:ff9b:1::/48`), NAT64 addresses that embed a local address, and
  interface-scoped addresses.
- **A failed or half-closed guest TCP flow could hold a goroutine and a flow
  slot forever.** The proxy now aborts on a write error or a non-EOF read
  error, and forwards a clean EOF as a half-close.
- **A guest dropped while its `AllowClient` check was running could still be
  admitted.** Fixed in the Tailcat integration patch (`removedAllow`).
- **The client socket protector could replace the exit node's protector** while
  sharing was active. `SetSocketProtector` is now ignored during an exit-node
  claim.
- **`StartExitNode` could run alongside an active client session.** It now
  refuses.
- **The Android client and exit-node roles could overlap.** A shared role
  interlock covers both, and the exit-node service has a bounded stop handoff.

### Android services

- **Shutdown races in the VPN service and controller**: notification updates
  and shutdown now share a lock, revocation callbacks are scoped to their
  session generation, and the socket protector is cleaned up on stop.
- **`shortService` timeouts were not handled.** They now complete the rejected
  start's cleanup.
- **The VPN kept retrying with backoff while Share this phone was active.** The
  exit-node refusal is now a permanent start failure, so there are no retry
  loops against it.
- **Stopping during `Prepare` could race session cleanup**, and a failed
  session stayed registered in the engine after it was closed. Closing a
  session now waits (bounded) for an in-flight `Prepare`, and a failed session
  is cleared once it is closed.

### Storage and profiles

- **`SealedPreferences` was not synchronized**, and a Keystore error could leave
  a stale cached key in use. Access is synchronized and the cached key is
  invalidated on error.
- **A failed profile write changed the in-memory profile list anyway.** Writes
  that fail now leave the list untouched, and the failure is reported to the UI.
- **Deleting the last profile left a dangling active profile id.** It is now
  cleared.
- **Legacy preference migration could run twice.** It is idempotent.

### Updater (`github` flavor)

- **The `FileProvider` was declared in every flavor.** It is now only in the
  `github` flavor, which is the only one with an updater.
- **Release metadata and downloads were under-validated.** The repo slug is
  validated, redirects are disabled on pinned HTTPS, HTTP reads are bounded,
  version comparison follows SemVer 2.0.0 precedence, the downloaded APK's
  version and signing lineage are verified (including out-of-order rotation
  lineage), and release page URIs are normalized so `..` segments cannot
  escape.

### UI

- **`FLAG_SECURE` could be cleared too early** when more than one secure screen
  was open. A reference-counted controller now owns the flag.
- **Token inputs were saved in `savedInstanceState`.** Secret inputs are kept
  out of it.
- **Notification deep links could fire again** on rotation or recreation. They
  are consumed once.
- **Starting a share without the notification permission** left the sharing
  notification invisible on Android 13+. The app now asks before sharing.
- **Layout problems**: the keyboard, system bars, scrolling, and wrapping rows
  on the add-profile dialog, settings, share, and speed-test screens.
- **TalkBack** labels and roles were missing or wrong on several controls.
- **UI events could be lost** when emitted with no collector. They are now
  buffered.
- **A speed-test report could call a test gateway-routed just because the
  tunnel read `CONNECTED`**, even when the test ran over device routes. The
  tunnel state is now read at the start of the test, and the report goes by the
  path the test actually took.
- **The copyable troubleshooting report could leak a token or address.** It now
  redacts `tc…` tokens, and its public IP redaction handles IPv6 and addresses
  wrapped in punctuation or prefixed by hex words.
- **A stale connection error stayed on the home screen after switching
  profiles.** It is cleared on a profile change.

## Verification

Host: Android unit tests for the GitHub flavor, and the Go tests, vet, and
fuzz seed corpus for `core-engine/` with the rebuilt AAR (hash and source hash
verified by CI).

CI on the commit this release is built from: `ci` and `formal` passed, and so
did the emulator suite, with both the no-gateway smoke job and the live
gateway job green against a real gateway. Earlier emulator runs on the same
commit failed with high latency and UDP loss while the gateway was degraded,
and passed once it recovered. No code change was involved.

Development APKs for both ABIs, signed with the pinned development key, with
the updater pointed at `OmarAlaaeldein/OpenTailcat`.

Not done this release: physical ARM64 dual-capture leak acceptance, a physical
phone as the share host, long-session battery and doze behavior, and device
tests of the full VPN lifecycle fixes. The client tunnel is still a
development preview and not a hardened privacy VPN.
