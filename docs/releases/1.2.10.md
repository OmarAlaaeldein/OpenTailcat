# OpenTailcat 1.2.10

Development build. Not a production privacy VPN. `ipv6` remains false.

Built with the `development` build type: release R8/resource optimization with
the existing development certificate and no debug UI tooling. `release` signing
remains separate; never debug-key-sign a release.

1.2.10 takes versionCode 23 to keep phone installs distinct from 1.2.9
(versionCode 22). It fixes the native crash behind
`VPN data plane failed: engine packet pump failed, tcp proxy panic, invalid
memory address or nil pointer dereference`, reported from a live device via
the 1.2.9 debug banner.

## What changed since 1.2.9

- Nil-dial hardening: a gateway dial returning `(nil, nil)` — no connection,
  no error — is now rejected fail-closed at every consumption site (TCP
  proxy, UDP flows, DNS-over-TCP, UDP capability probe, egress audit,
  tunnel DNS, speedtest TLS dial). Previously the nil connection reached
  track/copy/`Close` and panicked on flow teardown, tearing down a healthy
  tunnel over a single bad flow. Now only that flow fails (app-side RST)
  and the session stays RUNNING. Also guards a nil gVisor endpoint.
- Panic call-site reporting: contained pump/flow reports append the faulting
  function (e.g. `... @ com.tailcat.vpn/engine.(*netstackProxy).proxyTCP`),
  so future banners point straight at the code. Full stacks go to logcat.
- Tests: new `nil_dial_test.go` (nil TCP with full SYN→SYN-ACK→ACK handshake,
  nil UDP, nil DNS-over-TCP, `isNilConn`, `panicSite`). Negative control:
  with the guard stashed, the TCP test reproduces the exact reported log
  line and fails; with it, all pass.
- Version bump to 1.2.10 / versionCode 23. AAR rebuilt after the Go changes
  (Go 1.27.1 + NDK r29, 16 KB ELF alignment, verified Java signatures).
